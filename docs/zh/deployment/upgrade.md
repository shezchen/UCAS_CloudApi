# 升级指南

## 升级到凭证加密与 API Key 哈希存储

> **本次升级需要停机。** 启动新版本之前，请先停止所有正在运行的 AxonHub 实例。
> 滚动升级会导致仍在运行旧版本的实例无法通过 API Key 认证。

本次发布改变了两类敏感数据的存储方式：

- **API Key** 不再以明文保存。数据库只保留用于校验的 SHA-256 哈希，以及供界面
  展示的脱敏值（`ah-1a2b3c4d5...e5f6`）。
- **渠道的服务商凭证** 在配置了 `security.credential_encryption_key` 时使用
  AES-256-GCM 加密存储。

已有数据由启动时自动运行的回填任务完成转换。

### 为什么必须停机

第一个启动的新实例会重写整张 `api_keys` 表的 `key` 列，把每一个明文 Key 替换为
脱敏展示值。旧实例正是通过比对该列来完成认证的，因此从这一刻起，它会拒绝
**所有** API 请求 —— 不是部分请求，也不只是新建的 Key。

两个版本之间也不再互相传递缓存失效事件，因为缓存标识方案与存储格式一同做了版本
区分。在一个版本上被吊销的 API Key，在另一个版本上会一直有效，直到其缓存条目
过期。

### 升级步骤

1. **备份数据库。** 回填是不可逆的：明文 Key 一旦被替换为哈希与展示值，就无法再
   从数据库中恢复原值。这份备份是唯一的回退手段。

2. 如果希望加密存储渠道凭证，**准备一个凭证加密密钥**。可以这样生成：

   ```bash
   openssl rand -base64 32
   ```

   请将它保存在数据库之外的地方 —— 密钥管理服务，或由其注入的环境变量。
   **一旦丢失该密钥，所有渠道的服务商凭证都会随之丢失**，仅有数据库备份也无法
   找回。

3. **停止所有 AxonHub 实例。**

4. **启动一个新实例**，并配置好密钥：

   ```bash
   export AXONHUB_SECURITY_CREDENTIAL_ENCRYPTION_KEY="<第 2 步生成的密钥>"
   ```

   回填在启动过程中执行，任何异常都会导致启动失败，因此请先确认日志再继续。
   预期输出：

   ```
   backfilled api key hashes         {"count": 42}
   encrypted stored channel credentials  {"count": 7, "key_id": "94d9e4bf66cf"}
   ```

5. **启动其余实例。**

### 升级之后

**已有的 API Key 仍然可用。** 它们的原始值没有变化，改变的只是存储格式。区别在于
原始值无法再从 AxonHub 读取：界面上显示的是脱敏形式，Key 的完整值只在创建和轮换
时展示一次。没有记录下自己 Key 的用户需要通过轮换获取新的 Key。

### 之后再配置加密密钥

可以先不配置 `security.credential_encryption_key`，之后再补上；下次重启时会把仍
为明文的渠道凭证加密。反向则不行 —— 凭证一旦加密，未配置密钥的实例会直接拒绝
启动，而不是带着无法读取任何渠道的状态运行。

### 更换加密密钥

更换密钥不需要停机：

1. 将新密钥设为 `security.credential_encryption_key`，并把原密钥移入
   `security.credential_decryption_keys`：

   ```yaml
   security:
     credential_encryption_key: "<新密钥>"
     credential_decryption_keys:
       - "<原密钥>"
   ```

2. 重启。回填会用新密钥重新加密所有渠道，并在日志中输出新的 `key_id`。

3. 从 `credential_decryption_keys` 中移除原密钥，再重启一次。

不要跳过第 3 步之前的那次重启：任何仍由原密钥加密的数据都会变得无法读取，实例将
拒绝启动。

### 恢复备份

本版本导出的备份（格式 1.5）包含 API Key 的哈希，因此恢复出来的 Key 仍然可用。
更早版本导出的备份包含原始 Key，会在导入时完成哈希。

备份文件中的渠道凭证使用导出时所配置的密钥加密。请将密钥与备份一并保管，否则备份
将无法恢复。
